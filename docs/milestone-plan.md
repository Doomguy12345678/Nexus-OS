# Nexus-OS Milestone Plan

## Phase 0 — Alpha 0

Goal: prove the project can build a reproducible OS image artifact.

Completed:
- bootc image build prototype
- project status and decision record
- first image artifact and validation path

## Phase 1 — Alpha 1

Goal: choose the production base and establish the support model.

Completed:
- base comparison and weighted scoring
- hardware qualification template
- support and release policy design

Remaining:
- final base selection and engineering sign-off
- proven hardware validation data
- public support matrix and known issues

## Phase 2 — Beta readiness

Goal: qualify the distribution for limited public beta use.

Required tasks:
- finalize install and recovery flow
- prove update and rollback
- complete hardware validation across supported classes
- publish beta release notes and support matrix
- approve beta gate and release sign-off

## Phase 3 — Public Beta

Goal: launch an invite-only or early-access beta.

Required tasks:
- release candidate build and artifact signing
- known issues and escalation path live
- user onboarding and support process in place
- telemetry and diagnostics opt-in consent in place

## Phase 4 — Stable 1.0

Goal: mature the project into a supported Linux desktop for creators and gamers.

Required tasks:
- stable support matrix
- curated catalog maturity
- installed app cleanup and update policy
- security and maintenance cycle published
- long-term support plan for critical workloads

## Decision gate for each phase

Each phase must prove:

- the product still matches the stated mission
- core technical risks are under control
- support burden is understood and manageable
- product guidance is honest and evidence-based

If a phase cannot produce measured evidence, it is not ready to advance.
